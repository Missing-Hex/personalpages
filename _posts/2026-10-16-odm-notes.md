问题：数据配比（data mixing）的权重通常是在训练**前**就定死的。

+ The Pile 的做法：22 个 domain 的采样权重靠人工直觉拍板，作者自己也给不出为什么是这个比例
+ DoReMi 能自动学出权重，但要额外训练 reference 和 proxy 两个模型，代价高
+ 更要命的是，DoReMi 学出来的权重**跨 tokenizer 不迁移**——文章实测把 256k 词表上算出的权重换到 50k 词表，结果比人工权重还差 0.7%

所以文章要回答的是：能不能在训练过程中**在线**调整配比，而且几乎不引入额外开销？

### ODM as a Multi-Armed Bandit

![方法总览](/images/odm-overview.png)

insight：把每个 domain 看成老虎机的一条臂。"该从哪个 domain 采样"和"该拉哪台老虎机"本质上是同一个问题——一开始都不知道哪台出钱多，只能边试边学。

策略 $\pi(D)$ 就是各 domain 的采样概率，基于 Exp3 构造，由两部分线性组合：

$$
\pi_t(D_i) = (1 - K E_t)\frac{\exp(E_{t-1} \hat R_i)}{\sum_j \exp(E_{t-1} \hat R_j)} + E_t
$$

+ 左边是 Gibbs 分布（softmax），负责**利用**——奖励高的 domain 采样概率大
+ 右边的 $E_t$ 是均匀分布项，负责**探索**——保证每个 domain 永远有保底概率，不会被彻底饿死。$E_t$ 的上限是 $1/K$，取到上限时左边系数归零，整个策略退化成纯均匀采样
+ $E_t$ 随时间衰减：$E_t = \min(1/K,\ \sqrt{\ln K / (K t)})$，即 $1/\sqrt{t}$ 的节奏，先快后慢

注意 $E_t$ 在这里是**增益**（乘在奖励的指数上），不是温度（除在底下）。它一开始钉在 $1/K$、让分布接近均匀，随训练推进逐渐变小、分布被拉开——跟"先广撒网、后集中火力"的直觉一致。

相对标准 Exp3，文章只改了一处：**用滑动平均替代累计奖励**。

$$
\hat R_{i,t} = \alpha \hat R_{i,t-1} + (1 - \alpha)\frac{R_{i,t}}{\pi_{t-1}(D_i)}
$$

理由是标准 MAB 里每轮奖励权重相同，但训练场景下**我们只关心最近的奖励**——模型在变，早期的高 loss 不代表现在还值得多采。

### Designing the Reward

insight：奖励函数直接就用**当前这个 domain 的 training loss**，不额外花一分钱。

$$
R_{i,t} = L(f, x, y)
$$

理由是困惑度（perplexity，即 loss 的指数）本身就是"还有多少信息可学"的度量。某个 domain 的 loss 高，说明模型还没学会它，那就该多采一些。

这里最容易卡住的是符号：**loss 越小越好，而 MAB 要最大化 reward，岂不是反了？** 其实不反——同一个数，进优化器时叫 loss（要最小化），进老虎机时叫 reward（要最大化）。loss 在这里是**指北针，不是终点**：MAB 不是在优化 loss，而是在借用 loss 当作"哪个域还有货可学"的信号。

而且这么设计有个很实在的好处：loss 是训练本来就要算的量，所以**不增加任何额外的前向或反向传播**。论文报的额外墙钟开销是 0.000007%。

回头看 $\hat R$ 里那个除以 $\pi_{t-1}(D_i)$，它是重要性采样：采样概率低的 domain，观测到的 loss 要放大才能代表它的真实水平（类似抽样调查里，样本量少的群体要加权）。**这里有个内建的副作用**——它把分布往均匀方向拉。因为某个域被采得越少，分母越小，它的奖励被放大得越多，下一轮就越容易被采到。

### Results

1B 模型、50B token、The Pile 的 22 个 domain，对比 The Pile 人工权重（TPW）和两套 DoReMi 权重：

+ 达到 TPW 的最终验证困惑度，ODM 少用 **30%** 的迭代；对比 DoReMi-50k 少用 **19%**
+ 最终验证困惑度：比 TPW 低 4.8%，比 DoReMi-50k 低 2.4%，比 DoReMi-256k 低 4.9%
+ 5-shot MMLU：ODM 0.28416，对比 TPW 0.27469 相对提升 3%

有个发现挺关键：**DoReMi-256k 比人工权重还差 0.7%**，跟 DoReMi 原论文的结论直接矛盾。作者为此专门联系了原作者，重算了一套适配 50k 词表的权重才得到 DoReMi-50k。这件事说明 DoReMi "方法有效"和"产物通用"是两回事。

还有个我觉得值得琢磨的观察：**优化目标决定了结果的形状**。把 22 个域按"最好/中间/最差"分三档——

+ TPW（人工）：7 好 / 8 中 / 7 差，基本均匀散开
+ DoReMi-50k：**17 个挤在中间**，只有 3 个好、2 个差——这正符合它"最小化最坏情况超额损失"的目标
+ ODM：9 好 / 9 中 / 4 差

另外，ODM 学出来的分布**比人工权重更接近均匀**（图 4）。升得最多的是 PhilPapers、HackerNews、BookCorpus2，降得最多的是 Github、ArXiv、PubMed_Central，大约 4 万步后基本稳定。

### 一个被作者自己承认的弱点

训练**早期** ODM 的困惑度反而高于所有基线。作者归因于 micro-batch 的**同质性**：ODM 每个 micro-batch 只来自单一 domain，而基线是混域 batch。他们做了个归因实验——极端版（所有梯度步都用同一个域）会让这个现象加剧，验证了这个解释。

两条修复路线都是 future work，没做：减小 micro-batch（有 GPU 利用率代价），或者**只在 warmup 期间于 micro-batch 内混域**（论文倾向这条）。

### 一些补充观察

**ADO 后来对这篇的正式批评**：ODM 只看 loss 高低，不考虑**不可约损失**（irreducible loss），这会导致天生低熵的域（如代码、数学）被系统性低估。实证是 Github 域上 ODM 的验证 loss 为 1.54，而 ADO 是 1.40。换个说法：**有价值的高 loss 是"可学的难"，垃圾的高 loss 是"不可学的乱"**，ODM 的奖励函数把这两者混在一起了。

**复现上的缺口**：$\alpha$ 这个移动平均系数，论文全文只给了符号、没给数值，附录也没有。想复现得自己扫。

**搬到 robotics 会怎样**：直觉上"高 loss 多采"在机器人数据上更危险，因为机器人演示里的高 loss 很多来自噪声和失败片段，而不是"还没学会"。SCIZOR 那类方法恰好是先把这些清掉——**用 SCIZOR 过滤后再交给 ODM 调频率，两个方法的假设是互补的**。另外机器人数据规模小、训练步数短，$1/\sqrt{t}$ 的衰减节奏需要重新标定。
